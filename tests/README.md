# 시험

```bash
bash tests/run-all.sh
```

- **Node 22.18 이상**이 필요해요. 서버 함수(`supabase/functions/*/index.ts`)와 도구(`tools/*.mjs`)를 그대로 불러와 시험해서, 시험 코드와 실제 코드가 따로 놀지 않아요.
- 브라우저 시험과 접근성 검사는 `playwright`, `axe-core` 가 있을 때만 돌아가요. 없으면 건너뛰고 알려 줘요.
  ```bash
  npm i --no-save playwright axe-core    # 저장소 폴더에서. package.json 은 바뀌지 않고, node_modules 는 .gitignore 에 있어요
  ```
- 하나라도 실패하면 종료 코드 1 이에요.

## 무엇을 시험하나요
| 폴더 | 내용 |
|---|---|
| `node/` | 서버 함수 4개(진단·자동 채우기·사진·글 초안)의 입력 검사·한도·보안·자동 검사, 승인 글 내보내기(가짜 서버), 글 생성기(이스케이프·noindex·낡은 페이지 정리), 링크·앵커 존재 확인 |
| `browser/` | 화면 동작(모의 서버): 진단 실제 측정 모드, 자동 채우기, 사진 올리기, 발행 설정, 상담 접수 관리자, 글 초안 검수, 배너, 레퍼런스. 모두 데스크톱·모바일 포함 |
| `a11y/` | axe-core 로 랜딩·진단·방침·가이드·관리자 화면의 접근성 위반 검사 (데스크톱·모바일) |

모든 외부 서비스(Supabase, Gemini)는 **모의(mock)** 예요. 그래서 이 시험이 통과해도 **실제 Supabase·Gemini 와의 연결은 확인되지 않아요.** 처음 켤 때는 `supabase/*_SETUP.md` 의 확인 단계를 직접 해 보세요.

## 시험으로 확인되지 않는 것
- **SQL(021~025)**: 개발 중에 임시 PostgreSQL 16 에서 손으로 시험했고(권한·한도·승인 규칙), 이 폴더에는 자동 시험 파일이 없어요. 가짜 `storage`·`auth` 스키마를 썼으므로 실제 Supabase 에서 한 번 더 확인이 필요해요.
- 접근성은 자동 도구가 잡는 범위만이에요. 스크린 리더로 직접 읽어 보거나 키보드만으로 끝까지 써 보는 확인은 따로 해야 해요.
- 실제 Gemini 답변의 품질(글이 규칙을 얼마나 지키는지)은 시험할 수 없어요.
