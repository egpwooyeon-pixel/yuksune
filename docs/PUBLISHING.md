# 승인된 글 공개 방법 (정보 가이드)

승인된 글을 `/guide/` 페이지로 올리는 **수동 절차**예요. 일부러 자동 공개가 아니에요. 사람이 마지막으로 확인하고 직접 올려야 해요.

## 한눈에 보기
```
관리자 > 글 초안 (EGP)에서 승인
        ↓  (내 컴퓨터에서)
node tools/export-approved.mjs      → content/guides/<slug>.json 파일 생성 (한 번 더 자동 검사)
node tools/build-guides.mjs         → guide/<slug>.html 페이지 생성
git diff 로 눈으로 확인 → 커밋 → PR → 합치기 → 사이트 배포
```

## 1. 글 파일 내보내기
```bash
SUPABASE_URL=https://<프로젝트>.supabase.co SUPABASE_SERVICE_ROLE_KEY=<서비스 키> node tools/export-approved.mjs --dry-run
```
- `--dry-run` 으로 먼저 무엇이 나갈지 보고, 이상 없으면 `--dry-run` 을 빼고 실행해요. `--build` 를 붙이면 페이지까지 바로 만들어요.
- **서비스 키는 파일이나 저장소에 적지 마세요.** 터미널에서만 설정하고, 이 스크립트는 키를 출력하지 않아요. (Supabase 대시보드 > Project Settings > API 의 `service_role`. 이 키는 모든 권한이 있어요.)
- Node 22.18 이상이 필요해요.
- 승인된 글 중 **아직 안 내보낸 글**만 나가요(`--all` 은 전부). 같은 이름의 **다른 내용** 파일이 있으면 덮어쓰지 않아요(`--force` 로만).
- 아래 경우는 **건너뛰고 이유를 알려 줘요**(파일을 쓰지 않음): 승인이 아님 / 차단 항목 기록 / 샘플 글 / 형식 오류 / **내보내기 직전 자동 검사에서 차단 항목이 나옴**(서버 함수와 같은 검사 코드를 다시 돌려요). 건너뛴 글이 있으면 종료 코드가 1 이에요.

## 2. 페이지 만들기와 확인
```bash
node tools/build-guides.mjs
git diff --stat
```
- 글 파일(JSON)을 지우고 다시 만들면 **그 글의 낡은 페이지도 같이 지워져요**(생성기가 만든 표시가 있는 페이지만. 손으로 만든 파일은 건드리지 않음).
- 만들어진 페이지를 브라우저로 열어 **사실·문구·광고 표시**를 마지막으로 확인하세요.

## 3. 올리기
- 브랜치를 만들어 `content/guides/` 와 `guide/` 를 커밋하고 PR 로 합치면 사이트(Netlify)에 올라가요.
- **검색 노출은 기본 꺼짐**이에요. `content/guides/_site.json` 의 `indexable: true` 와 `baseUrl`(공개 주소)을 **둘 다** 정해야 검색에 보이도록(noindex 해제, sitemap 생성) 바뀌어요. 정하기 전에는 모든 글이 `noindex` 예요. (`sample: true` 글은 항상 noindex)
- 검색에 노출하려면 사이트 루트의 `robots.txt` 에서 `/guide/` 를 막고 있지 않은지, `guide/sitemap.xml` 을 검색 도구에 등록할지도 정해야 해요.

## 글 내리기 (공개 취소)
1. `content/guides/<slug>.json` 을 지우고 `node tools/build-guides.mjs` 를 실행해요(낡은 페이지가 같이 지워짐).
2. 커밋 → PR → 합치기. 배포 후에는 검색엔진 캐시에 남을 수 있어요.
3. 잘못된 글이 DB 에 `approved` 로 남아 있으면 다시 내보내질 수 있어요. DB 에서 해당 초안을 반려 처리하거나(승인된 글은 화면에서 바꿀 수 없어 SQL 로 처리) 내보낸 기록(`exported_at`)을 확인하세요.

## 공개 전 체크리스트 (사람이 확인)
- [ ] 업체가 글 내용과 공개를 확인했다 (사용 동의)
- [ ] 글의 모든 사실을 업체가 준 정보와 대조했다 (가격·효과·후기·순위·자격 없음)
- [ ] 광고 표시와 안내 문구가 페이지에 보인다
- [ ] 병원·의료·법률 업종은 전문가 검토(의료광고 규정 등)를 마쳤다
- [ ] 연락처·주소·링크가 업체가 준 정보와 같다
- [ ] 사진을 쓴다면 사용 권한과 개인정보(얼굴 등)를 확인했다

## 검토했지만 만들지 않은 방식: 승인하면 자동으로 사이트에 공개 (Netlify Function)
승인된 글을 DB 에서 읽어 서버에서 HTML 을 그리는 방식이에요. 장점은 커밋 없이 바로 공개된다는 것, 단점은 아래와 같아서 **지금은 만들지 않았어요**.
- 라이브 사이트(체험단과 같은 Netlify 사이트)의 배포 설정(`netlify.toml`)을 바꿔야 하고, 함수 빌드 오류가 **사이트 전체 배포 실패**로 이어질 수 있어요. 미리보기 PR 로 먼저 검증해야 해요.
- 사람의 마지막 확인(위 체크리스트) 없이 승인만으로 공개돼서, 병원·의료 글에서 위험이 커져요.
- Supabase Edge Function 으로 HTML 을 직접 내려주는 것은 불가능해요(HTML 응답이 텍스트로 바뀜). [Uncertain] 현재 정책은 Supabase 문서로 확인이 필요해요.
- 하려면: 승인 기준·체크리스트가 정착되고, 별도 도메인/사이트로 분리한 뒤에 검토하는 것을 권해요.

## 상태
- 내보내기·정리 코드는 모의 서버(PostgREST 모양)와 임시 폴더로 시험했어요(위험한 글이 섞여 있어도 안전한 글만 나가는지, 키가 출력에 없는지, 재실행·덮어쓰기·dry-run, 낡은 페이지 정리).
- **실제 Supabase 와 실제 승인 글로는 실행해 보지 않았어요.** 실제 PostgREST 응답 형식(`select=*`, `status=eq.approved`, `exported_at=is.null`, PATCH)은 문서 형식을 기준으로 가정했어요.
