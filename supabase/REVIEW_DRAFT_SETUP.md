# AI 리뷰 원고(블로그) 설정

운영자가 매장 리뷰(크롬 확장프로그램으로 모은 것)와 사진 URL을 넣으면 AI(Gemini)가 블로그 원고 **초안**을 쓰고, 운영자가 검수해서 **검수완료** 표시를 하는 기능이에요.
화면: 관리자 > **AI 리뷰 원고 (체험단)** (`admin-review-drafts.html`).

## `글 초안 (EGP)` 과 다른 점
같은 레포에 있는 `admin-drafts.html`(EGP 글 초안)과 구조는 비슷하지만 성격이 다릅니다.

| | 글 초안 (EGP) | AI 리뷰 원고 (체험단) |
|---|---|---|
| 입력 | 운영자가 확인한 "사실" 목록 | 실제 고객 리뷰 텍스트(+사진) |
| 용도 | AI 검색 노출용 정보 가이드 글 | 매장 블로그 홍보 원고 |
| 과장·금지어 자동 차단 | 있음(의료광고 등 규제 대상) | **없음** — 손님 후기 기반 홍보 원고는 같은 규제 대상이 아니라서, 문구 확인은 운영자 눈으로 함 |
| "검수완료"의 의미 | 다음 공개 발행 단계로 넘어갈 수 있음 | **발행이 아님.** 이 기능엔 발행 파이프라인이 없고, 운영자가 원고를 복사해서 네이버 블로그 등에 직접 올리는 걸 전제로 함 |
| 리뷰·사진 수집 | 해당 없음 | **포함되지 않음.** 크롬 확장프로그램(네이버 플레이스/스마트스토어/구글 리뷰 수집)으로 모은 CSV에서 리뷰·사진URL을 옮겨 붙이는 방식 |

## 원칙 (코드에 들어 있어요)
1. **AI는 초안만.** 검수완료는 운영자가 **검수 메모(5자 이상)**를 남겨야 하고, 처리한 사람·시각이 기록돼요.
2. **입력한 리뷰만 근거로.** AI에게 "리뷰에 없는 내용(가격·효능·순위 등)을 지어내지 말라"고 지시해요. 다만 글초안(EGP)과 달리 서버가 자동으로 과장 표현을 차단하지는 않으니, 올리기 전에 반드시 사람이 리뷰 원문과 대조하세요.
3. **사진 설명(캡션)은 실제 사진 이미지를 함께 Gemini에 보내서** 쓰게 해요(리뷰 텍스트만 보고 추측하지 않음) — 사진과 캡션이 안 맞는 문제를 줄이기 위해서예요.
4. 업체 정보·리뷰·사진 URL은 운영자가 수정 화면에서 바꿀 수 없어요(제목·해시태그·본문·사진 설명만 수정 가능).

## 구성
| 파일 | 역할 |
|---|---|
| `supabase/027_review_drafts.sql` | 원고 표(`review_drafts`). 브라우저는 **읽기만**(운영자), 쓰기는 서버 함수와 검수 함수로만. `review_review_draft`: 운영자만·메모 필수·초안 상태에서만 |
| `supabase/functions/review-draft` | 원고 만들기(`generate`)와 수정 저장(`save`). **운영자 로그인 확인**, 사진 다운로드+Gemini 호출 |
| `admin-review-drafts.html/.js` | 목록, 새 원고, 제목·해시태그·본문·사진 설명 수정, 검수 메모·검수완료·반려 |

## 켜는 순서
1. Supabase SQL Editor 에서 `supabase/027_review_drafts.sql` 실행 (008 이후). 여러 번 실행해도 안전해요.
2. `review-draft` 함수 배포. 비밀값 `GEMINI_API_KEY` 가 필요해요(글초안·AI 진단 기능과 **같은 키**를 그대로 씁니다). 모델은 `GEMINI_MODEL`(쉼표로 여러 개 가능, 기본 `gemini-3.8-flash`).
   - JWT 확인은 **켜진 기본값** 그대로 두세요. 함수 안에서 한 번 더 운영자인지 확인해요.
3. 관리자로 로그인 → **AI 리뷰 원고 (체험단)** → **새 원고 만들기**.
4. 리뷰·사진 URL은 크롬 확장프로그램의 "리뷰 CSV 다운로드"를 열어서, "리뷰내용" 칸과 "사진URL" 칸(' | '로 구분된 값을 줄바꿈으로 바꿔서)을 옮겨 붙이면 됩니다.
5. 처음에는 가상 업체/리뷰로 시험해 보고, 원고가 리뷰 내용과 맞는지, 사진 설명이 실제 사진과 맞는지 눈으로 확인하세요.

## 상태
- `027_review_drafts.sql`: `025_drafts.sql`과 같은 RLS·권한 구조를 그대로 따랐어요. 실제 Supabase 에서 실행해 검증하지 않았습니다.
- `review-draft`: 모의 의존성(가짜 Gemini·가짜 사진 다운로드·가짜 DB)으로 입력 검사, 프롬프트 내용(리뷰·요청사항 반영, 사진 인라인 전달), 모델 출력 조립, 실패 시 저장되지 않는지, 수정 저장 규칙을 시험했어요 (`tests/node/review-draft.test.mjs`, `node tests/node/review-draft.test.mjs` 로 실행, 16개 모두 통과).
- **실제 Gemini 와 실제 Supabase 로는 실행해 보지 않았어요.** 사진 다운로드가 실제 네이버/구글 사진 URL(만료되거나 리퍼러 제한이 있을 수 있음)에서 잘 되는지, 실제 AI가 쓴 원고 품질이 쓸 만한지는 첫 실행에서 확인해야 합니다.
- 화면(`admin-review-drafts.js`)은 `admin-drafts.js`와 같은 방식(바닐라 JS, textContent/value 만 사용)으로 만들었지만, 브라우저에서 직접 켜보는 시험(Playwright)은 아직 작성하지 않았습니다.
