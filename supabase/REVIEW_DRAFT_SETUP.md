# AI 리뷰 원고(블로그) 설정

매장 리뷰(크롬 확장프로그램으로 모은 것)와 사진 URL을 넣으면 AI(Gemini)가 블로그 원고를 쓰는 기능이에요. 두 화면이 있어요:

- **회원용** `review-draft.html` (사이트 메뉴 "AI 리뷰 원고" — 플레이스 메뉴와 커뮤니티 사이): **사업자 인증 승인된 회원**이 직접 자기 매장 리뷰로 원고를 만들고, 그 자리에서 복사해서 쓰는 셀프서비스 화면. 검수 절차 없음, 하루 생성 개수 한도 있음.
- **운영자용** `admin-review-drafts.html` (관리자 > AI 리뷰 원고 (체험단)): 운영자가 직접 만들거나, **회원이 만든 원고를 전부 모아보고** 검수 메모를 남기는 화면. 한도 없음.

둘 다 같은 표(`review_drafts`)와 같은 Edge Function(`review-draft`)을 씁니다 — rank.html("내 플레이스 순위확인하기")이 회원용 화면과 관리자 화면을 같은 데이터로 나눠 보여주는 것과 같은 구조예요.

## `글 초안 (EGP)` 과 다른 점
같은 레포에 있는 `admin-drafts.html`(EGP 글 초안, 운영자 전용)과 구조는 비슷하지만 성격이 다릅니다.

| | 글 초안 (EGP) | AI 리뷰 원고 (체험단) |
|---|---|---|
| 누가 쓰나 | 운영자만 | **사업자 인증 승인 회원도 직접 사용** (+ 운영자) |
| 입력 | 운영자가 확인한 "사실" 목록 | 실제 고객 리뷰 텍스트(+사진) |
| 용도 | AI 검색 노출용 정보 가이드 글 | 매장 블로그 홍보 원고 |
| 과장·금지어 자동 차단 | 있음(의료광고 등 규제 대상) | **없음** — 손님 후기 기반 홍보 원고는 같은 규제 대상이 아니라서, 문구 확인은 사람 눈으로 함 |
| "검수완료"의 의미 | 다음 공개 발행 단계로 넘어갈 수 있음 | **발행이 아님.** 이 기능엔 발행 파이프라인이 없고, 원고를 복사해서 네이버 블로그 등에 직접 올리는 걸 전제로 함 — 회원용 화면에는 검수 절차 자체가 없음(만들면 바로 복사해서 씀) |
| 리뷰·사진 수집 | 해당 없음 | **포함되지 않음.** 크롬 확장프로그램(네이버 플레이스/스마트스토어/구글 리뷰 수집)으로 모은 CSV에서 리뷰·사진URL을 옮겨 붙이는 방식 |
| 호출 한도 | 없음(운영자만) | **회원은 하루 `REVIEW_DRAFT_DAILY_LIMIT`건**(기본 5) — 공유 Gemini 무료 티어를 여러 회원이 같이 쓰기 때문. 운영자는 한도 없음 |

## 원칙 (코드에 들어 있어요)
1. **입력한 리뷰만 근거로.** AI에게 "리뷰에 없는 내용(가격·효능·순위 등)을 지어내지 말라"고 지시해요. 다만 글초안(EGP)과 달리 서버가 자동으로 과장 표현을 차단하지는 않으니, 올리기 전에 반드시 리뷰 원문과 대조하세요(회원용 화면에는 이 안내 문구가 그대로 보여요).
2. **사진 설명(캡션)은 실제 사진 이미지를 함께 Gemini에 보내서** 쓰게 해요(리뷰 텍스트만 보고 추측하지 않음) — 사진과 캡션이 안 맞는 문제를 줄이기 위해서예요.
3. **조회는 RLS로 분리**: 운영자는 전체, 회원은 `created_by = auth.uid()`인 자기 것만 보여요(028 SQL). 쓰기(생성·수정)는 브라우저가 직접 못 하고 항상 서버 함수(service_role)만 해요.
4. 수정 저장(`action:"save"`)·검수 완료/반려는 **운영자만** — 회원용 화면엔 그 버튼 자체가 없어요.
5. 업체 정보·리뷰·사진 URL은 운영자 수정 화면에서도 바꿀 수 없어요(제목·해시태그·본문·사진 설명만 수정 가능).

## 구성
| 파일 | 역할 |
|---|---|
| `supabase/027_review_drafts.sql` | 원고 표(`review_drafts`) 생성. `review_review_draft`: 운영자만·메모 필수·초안 상태에서만 |
| `supabase/028_review_drafts_member.sql` | 조회 RLS를 "운영자는 전체, 회원은 본인 것만"으로 확장 |
| `supabase/functions/review-draft` | 원고 만들기(`generate`, 운영자+승인회원)와 수정 저장(`save`, 운영자만). 호출자의 role·business_status 확인, 회원 일일 한도 확인, 사진 다운로드+Gemini 호출 |
| `review-draft.html/.js` | **회원용**: 폼 + 내가 만든 원고 목록 + 복사 버튼. 사업자 인증 미승인 회원에겐 안내+"광고주 인증하러 가기" 링크 |
| `admin-review-drafts.html/.js` | **운영자용**: 전체 목록, 새 원고, 제목·해시태그·본문·사진 설명 수정, 검수 메모·검수완료·반려 |
| `common.js` | 사이트 메뉴에 "AI 리뷰 원고" 링크 추가 (데스크톱: 플레이스 순위확인 옆, 모바일: 전체메뉴의 별도 칸) |

## 켜는 순서
1. Supabase SQL Editor 에서 `supabase/027_review_drafts.sql` → `supabase/028_review_drafts_member.sql` 순서로 실행 (008 이후). 여러 번 실행해도 안전해요.
2. `review-draft` 함수 배포(또는 재배포). 비밀값 `GEMINI_API_KEY` 가 필요해요(글초안·AI 진단 기능과 **같은 키**를 그대로 씁니다). 선택: `GEMINI_MODEL`(기본 `gemini-3.8-flash`), `REVIEW_DRAFT_DAILY_LIMIT`(회원 1인당 하루 생성 한도, 기본 5).
   - JWT 확인은 **켜진 기본값** 그대로 두세요. 함수 안에서 한 번 더 로그인·등급을 확인해요.
3. **회원 테스트**: 사업자 인증이 승인된 회원 계정으로 로그인 → 사이트 메뉴 **"AI 리뷰 원고"** → 리뷰 붙여넣고 원고 만들기.
4. **운영자 테스트**: 관리자로 로그인 → **AI 리뷰 원고 (체험단)** → 회원이 만든 원고가 보이는지 확인(여러 명이 만들면 전체가 여기 모여요).
5. 리뷰·사진 URL은 크롬 확장프로그램의 "리뷰 CSV 다운로드"를 열어서, "리뷰내용" 칸과 "사진URL" 칸(' | '로 구분된 값을 줄바꿈으로 바꿔서)을 옮겨 붙이면 됩니다.

## 상태
- `027`/`028` SQL: `025_drafts.sql`·`rank.html`의 RLS·권한 구조를 그대로 따랐어요. 실제 Supabase 에서 실행해 검증하지 않았습니다.
- `review-draft` 함수: 모의 의존성(가짜 Gemini·가짜 사진 다운로드·가짜 DB)으로 운영자/승인회원/미승인회원/비로그인 4가지 등급, 회원 일일 한도, 프롬프트 내용, 모델 출력 조립, 실패 시 저장 안 됨, 수정 저장 권한을 시험했어요 (`node tests/node/review-draft.test.mjs`, 18개 모두 통과).
- 화면: `admin-review-drafts.js`는 `tests/browser/review-drafts-admin.test.js`(26개), `review-draft.js`(회원용)는 `tests/browser/review-draft-member.test.js`(13개) — 둘 다 모의 Supabase로 권한·목록·생성·오류 문구·모바일 화면을 시험, 전부 통과.
- **실제 Gemini 와 실제 Supabase 로는 실행해 보지 않았어요.** 사진 다운로드가 실제 네이버/구글 사진 URL(만료되거나 리퍼러 제한이 있을 수 있음)에서 잘 되는지, 실제 AI가 쓴 원고 품질이 쓸 만한지, RLS가 실제로 "내 것만" 보여주는지는 첫 실행에서 확인해야 합니다.
