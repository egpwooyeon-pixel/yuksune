# 업플로우 공식 API 연결 (관리자 > 네이버 플레이스)

관리자 화면 **네이버 플레이스**는 업플로우 계정에 이미 등록·수집된 순위를 읽어 와서 보여 줘요.
페이지를 열거나 새로고침해도 **새 검색을 실행하지 않아요**(읽기만). 1회 검색·재검색·등록·그룹 이동은 버튼을 눌렀을 때만 실행돼요.

## 한눈에
| 항목 | 값 |
|---|---|
| 화면 | 관리자 > 네이버 플레이스 (`admin.html#place`) |
| 서버 함수 | `upflow-place` (필수), `upflow-webhook` (선택) |
| 비밀값 (Supabase > Edge Functions > Secrets) | `UPFLOW_API_KEY` (필수), `UPFLOW_WEBHOOK_SECRET` (웹훅을 쓸 때만) |
| SQL | `024_place_links.sql` (매장·캠페인 연결), `026_upflow_events.sql` (웹훅 쓸 때만) |
| API 주소 | `https://upflow.co.kr/api/v1` (코드에 고정) |

키는 서버(Edge Function)에서만 읽어요. 브라우저·로그·응답에는 키, 회원 정보, 업스트림 인증 헤더가 나가지 않아요. (`/auth/verify` 응답에서는 승인 여부·권한·슬롯·오늘 검색 사용량만 추려서 보내요.)

## 설정 순서
1. 업플로우 개발자 페이지(https://upflow.co.kr/my/developer)에서 API 키를 발급해요. 승인이 필요하고, 키에는 읽기(read) 또는 읽기·쓰기(write) 권한이 있어요.
2. Supabase > Edge Functions > **Secrets** 에 `UPFLOW_API_KEY` 를 등록해요. (채팅·GitHub 에 올리지 마세요)
3. SQL Editor 에서 `024_place_links.sql` 을 실행해요.
4. Edge Functions 에서 `upflow-place` 함수를 만들고 `supabase/functions/upflow-place/index.ts` 를 붙여 넣어 Deploy 해요. (Settings 의 Verify JWT 는 OFF 로 둬도 돼요. 함수 안에서 운영자 로그인을 확인해요)
5. 관리자 > 네이버 플레이스 를 열어요. 키가 없으면 "테스트 데이터"로 보여 줘요.

## 권한과 사용량
- 읽기(read): 목록, 날짜별 이력, 중복 확인, 순위 요약, 1회 검색.
- 쓰기(write)에서만: 키워드 등록(최대 50건씩), 그룹 이동, 재검색 요청. 화면에서 막고, 서버도 `/auth/verify` 로 권한을 다시 확인해서 막아요. 권한을 알 수 없으면 쓰기를 거절해요.
- 화면 위에 **추적 슬롯**(등록된 키워드 수)과 **오늘 검색 사용량**을 따로 보여 줘요. 1회 검색·재검색은 업플로우 웹과 함께 쓰는 일일 검색 사용량에 합산돼요.
- 오류는 승인 필요 / 키 설정 오류 / 권한 부족 / 분당 호출 초과 / 일일 검색 한도 초과 / 슬롯 부족 / 중복으로 나눠 보여 줘요.
- 429 에 `Retry-After`(10초 이내)가 있을 때만 **읽기**를 최대 2번 다시 시도해요. 등록·1회 검색·재검색은 자동으로 되풀이하지 않고, 같은 요청은 30초 안에 서버에서도 막아요.

## 화면 사용
- **순위 추적**(기본): 키워드 기준 / 매장 기준, 매장·캠페인·그룹 필터, 시작일 순위, 최신 순위, 직전 수집 대비(연속된 날짜일 때만 '전일 대비'), 최근 7일, 최고 순위, 마지막 수집, 메모. 행을 펼쳤을 때만 날짜별 이력을 읽어요. 목록은 `ranks_summary` 로 보이고, **순위 요약 새로고침**은 한 번에 최대 200개 ID 로 읽어요.
- 시작일 순위는 연결한 캠페인의 등록일(또는 직접 정한 시작일)의 기록만 써요. 그날 기록이 없으면 '미수집'이고, 첫 수집값으로 대체하지 않아요.
- **키워드 등록**: 한 줄에 `키워드, 플레이스 주소 또는 ID`. 먼저 **중복 확인**(키워드 + 플레이스 코드 + 검색 모드) → 새 항목만 50건씩 등록 → 항목별 결과(신규 등록 / 기존 이력 복원 / 중복 / 입력 오류 / 슬롯 부족). 실패한 줄만 입력칸으로 되돌려 다시 보낼 수 있어요. 이미 있는 키워드는 기존 추적 ID 를 우리 매장·캠페인에 연결해요.
- **연결 해제**는 우리 사이트의 연결만 지워요. 업플로우의 추적 중지·휴지통 이동은 업플로우 웹에서 해 주세요.
- 재검색: 접수되면 '재검색 접수'(처리 중) → 접수 시각 이후에 수집된 새 기록이 확인될 때만 완료로 바꿔요. 잠깐 확인한 뒤에도 안 끝나면 '처리 중'으로 남겨요.
- 검색 조건(검색 모드·기기·출처)이 다른 기록끼리는 비교·차트 이어붙이기를 하지 않아요.
- 엑셀(CSV): 필터 결과를 내려받아요(엑셀에서 열려요).

## 웹훅 (선택)
1. SQL Editor 에서 `026_upflow_events.sql` 실행.
2. Edge Functions 에서 `upflow-webhook` 을 만들고 `supabase/functions/upflow-webhook/index.ts` 를 Deploy. **Verify JWT 는 반드시 OFF** (업플로우가 부르는 주소라서요. 대신 서명을 확인해요).
3. Secrets 에 `UPFLOW_WEBHOOK_SECRET` 등록.
4. 업플로우 개발자 페이지에서 웹훅 주소(`https://<프로젝트>.supabase.co/functions/v1/upflow-webhook`, 이벤트 `rank.changed` · `refresh.completed` · `refresh.failed`)를 **직접 등록**. (이 화면은 웹훅 등록 요청을 보내지 않아요)
- 원본 본문과 `UPFLOW_WEBHOOK_SECRET` 으로 HMAC-SHA256 을 계산해 `X-UpFlow-Signature` 와 비교해요. 틀리면 처리하지 않고 401. `X-UpFlow-Delivery` 로 같은 전달의 중복 처리를 막아요. 5초 안에 응답해요.
- 웹훅은 '이 키워드의 이력을 다시 읽으라'는 표시일 뿐이에요(순위 데이터는 저장하지 않아요). 표시된 키워드는 목록에 "새 기록 신호"로 보이고, 행을 펼치면 다시 읽어요.
- 실패한 전달은 재전송되지 않으니 놓쳐도 '목록 다시 읽기'로 따라잡아요. 웹훅이 없어도 화면은 그대로 동작해요.

## 검증 상태
- **실제 업플로우 API 로는 한 번도 확인하지 못했어요** (이 개발 환경에서 업플로우에 접속할 수 없고 키도 없어요). 응답 필드 이름·오류 코드·서명 형식·요청 본문은 여러 이름 후보를 허용하는 방식으로 가정했어요. 첫 실호출 때 확인하고, 다르면 `place-normalize.js`(응답 해석)와 `upflow-place/index.ts`(요청 본문) 한 곳씩만 고치면 돼요.
- 모의 응답으로 확인한 것: 연결 상태 요약, 읽기/쓰기 권한 차단, 목록 페이지 나누기, 이력·요약·중복 확인 요청 형태, 대량 등록의 항목별 결과, 409 DUPLICATE, 429·Retry-After, 재검색 대기, 웹훅 서명 실패·중복 수신, 화면 동작(데스크톱·모바일).
